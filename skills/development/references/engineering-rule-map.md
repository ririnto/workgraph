# Engineering rule map

This map records Workgraph's adaptations of Lauren Tan's [All Code Is Slop (Except Mine)](https://ai.engineer/talks/O_zcc6Xl12g-all-code-is-slop-except-mine).
Times refer to elapsed time in the 17:31 talk.
The examples and reported business metrics describe the speaker's environment.

| Time | Practice | Owner or rule | Effect or evidence |
| --- | --- | --- | --- |
| 01:32–02:41 | Make correct behavior the default through API design, types, and module ownership. | [Development automation](../SKILL.md#automation) | Shared interfaces prevent callers from reaching invalid states and retain only required effects. |
| 02:09–03:21 | Prefer compiler, lint, and deterministic tests for corrections they can express. | [Lint rule guidance](lint-rules.md) | Local and CI commands report invalid syntax or behavior reproducibly. |
| 02:09–02:41 | Use runtime and formal checks for properties and product intent, with prose for judgment. | [Development verification](../SKILL.md#verification) and [instruction design](instruction-design.md) | Check actual transitions and effects, with human judgment for scope and meaning. |
| 03:21–04:39, 08:54, 14:55–15:27 | Prevent new workarounds, migrate callers, and remove old patterns. | [Lint rule guidance](lint-rules.md) and [refactoring](../playbooks/refactoring.md) | Remove examples agents could copy after preserving required behavior and resources through the replacement. |
| 04:39–06:01 | Restrict product `useEffect` access and give synchronization an owner. | [React effects](react-electron.md#react-effects) and `eslint/no-restricted-imports` | Avoid effects for derivation and user actions, preserve subscription and cleanup behavior in the integration. |
| 06:01–06:32 | Separate Electron main and renderer code in the directory and dependency graph. | [Electron process imports](react-electron.md#electron-process-imports) and the dependency-cruiser rules | Block resolved cross-process paths that can bring blocking work into the renderer. |
| 06:32–07:12 | Remove workaround justifications in docs and keep case-specific corrections local. | [Documentation and comments](../SKILL.md#documentation-and-comments), [instruction design](instruction-design.md), and `comments/no-hidden-notes` | Parsed hidden notes can be flagged mechanically, while visible prose and policy scope need review. |
| 07:12–08:20 | Keep imperative timers out of product coordination. | [Scheduled work](react-electron.md#scheduled-work) and `eslint/no-restricted-globals` | Moving lifecycle work to its owner avoids repeated timer allocation and stale callbacks while preserving required timing. |
| 07:44–08:54 | Remove body narration, commented-out code, and stale paths. | [Local lint assets](lint-rules.md#adopt-a-lint-asset), `comments/no-body-comments`, `comments:no-body-comments`, Go `comments`, `commentedOutCode`, `commentedOutImport`, `unused`, `standard:no-unused-imports`, and `MD053` | Syntax and dead-path checks flag concrete cases without editing code. |
| 08:20–08:54 | Keep declaration contracts, consumed directives, legal text, and verified external constraints. | [Effect checks](side-effects.md) | Removing a directive can change lint, formatting, coverage, build output, or documentation, so preserve its actual consumer. |
| 08:54–09:30 | Put the correct next action in lint messages. | [Lint rule guidance](lint-rules.md) | A diagnostic identifies the prohibited form and directs the author to the owning API, declaration, or cleanup. |
| 09:30–10:01, 12:43 | Review acceptance artifacts that show what ran and what happened. | [Delivery evidence](../../delivery/SKILL.md#retain-validation-evidence) | Attach the relevant video, screenshot, trace, diagram, model check, or proof to support the behavior under review. |
| 10:01–10:33 | Run the application and debug it through its real interfaces. | [Runtime verification](runtime-formal-evidence.md#runtime-verification) | Browser drivers or devtools can observe the actual UI, events, and performance. |
| 10:01–10:33 | Maintain user-facing feature names and access paths for recurring verification. | [Runtime verification](runtime-formal-evidence.md#runtime-verification) | The feature map lets reviewers and drivers exercise the same intended flow. |
| 10:33–11:06 | Reuse testable drivers and CLIs. | [Runtime verification](runtime-formal-evidence.md#runtime-verification) | Repeated runs share setup and actions and can reproduce findings. |
| 10:33–11:37 | Model check concurrent flows and prove selected algorithm properties. | [Invariants and generated actions](runtime-formal-evidence.md#invariants-and-generated-actions) | TLA+ checks modeled transitions and Lean checks the stated theorem under its assumptions. |
| 11:37–12:43 | Explore UI behaviors with generated actions and explicit properties. | [Invariants and generated actions](runtime-formal-evidence.md#invariants-and-generated-actions) | Bombadil checks properties on explored interactions and produces replay evidence for failures. |
| 12:43–13:18 | Inspect statecharts beside visible runtime evidence. | [Invariants and generated actions](runtime-formal-evidence.md#invariants-and-generated-actions) | Reviewers can compare visible outcomes with expected states, guards, and failure transitions. |
| 09:30, 14:55–16:20 | Require reliable checks before scaling automation. | [Release-triggered verification](runtime-formal-evidence.md#release-triggered-verification) | The deployment and integration policies retain their own acceptance and authority requirements. |
| 16:20–16:56 | Trigger runtime exploration of the released build and route reproduced failures to fixes. | [Release-triggered verification](runtime-formal-evidence.md#release-triggered-verification) and [Delivery](../../delivery/SKILL.md#establish-merge-authority) | The release event identifies the build and retained evidence supports authorized fix publication and integration. |
